# E2E — Nabbit

What this is: a Playwright (TypeScript) browser suite exercising the real Angular PWA, the real backend handlers (via the local Express server) and LocalStack DynamoDB/S3 together, on a Pixel 7 viewport. Mirrors `BluefinWiki/e2e` (Playwright 1.63, no `webServer`: the stack is started separately), but brings its own stack script because the ports must not collide with other local projects.

Not folded into `../frontend/SYSDOC.md` or the backend docs because it spans both and owns its own lifecycle (stack up/down, fixtures).

## How the stack is wired

LocalStack 3 (`s3,dynamodb`) in a uniquely named container, `backend/scripts/init-local.mjs` for the table/bucket, the backend's local server with `NODE_ENV=development`, and the frontend built with the `e2e` configuration (auth disabled; its mock token is a JWT-shaped string whose `sub` the local backend reads). The URL-import journey uses the dev-server-only fixture hook, `backend/src/e2e-fixture-fetch.ts`: with `NODE_ENV=development`, `NABBIT_E2E_FIXTURE_FETCH=1` and a loopback `NABBIT_E2E_FIXTURE_ORIGIN`, `local.ts` gives `safeFetch` a resolver and transport that serve only `https://nabbit-fixtures.test/*` from the fixture site. `safe-fetch.ts` and the Lambda handlers are untouched and never read the flag (unit-tested in `backend/test/e2e-fixture-fetch.test.ts`). Instagram auto-fetch is exercised with `NABBIT_E2E_INSTAGRAM_HOSTS=ig.nabbit-fixtures.test` (set by `stack.mjs`; `isInstagramUrl` honours it ONLY when `NODE_ENV=development`, unit-tested to be ignored otherwise) plus `extraInstagramHosts` in the generated, uncommitted `environment.e2e.ts` so the frontend also treats that host as Instagram (the fixture hook answers for both `nabbit-fixtures.test` and `ig.nabbit-fixtures.test`). The AI journey uses a second dev-only hook, `installE2eFakeLlm` in `local.ts` (NODE_ENV=development and `NABBIT_E2E_FAKE_LLM=1`, set by `stack.mjs`): a stub `LlmParser` that returns a fixed "Fake AI Soup" recipe for text containing `[[fake-llm]]`, and a NotRecipe verdict (reason "Fake: this is a travel vlog") for text containing `[[fake-not-recipe]]` (checked first; a forced `forceRecipe` call gets the soup instead, matching the real parser, which has no not-a-recipe exit when forced). YouTube is exercised with the third fixture hostname `yt.nabbit-fixtures.test`: `NABBIT_E2E_YOUTUBE_HOSTS` (set by `stack.mjs`; honoured ONLY when `NODE_ENV=development`) makes the backend treat it as YouTube, and `extraYoutubeHosts` in the generated `environment.e2e.ts` does the same for the frontend. The fixture fetch maps `https://yt.nabbit-fixtures.test/watch?v=<id>` (a well-formed 11-character id) to `fixtures/site/yt/<id>.html`; caption tracks the watch pages point at are `fixtures/site/captions/*` (the static server serves `.xml` as `text/xml`). The suite imports more than the 30/hour cap, so `stack.mjs` sets `NABBIT_E2E_IMPORT_LIMIT=1000` (`ImportDeps.importLimit`; only honoured by the fixture-fetch hook in `local.ts` and only above 30). The FullyRested import cases 09 and 10 (`backend/tests/api`) are local-only and need the fake LLM; the Playwright stack has it on.
