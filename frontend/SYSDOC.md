# Frontend — Nabbit

What this is: the Angular 22 installable PWA (standalone components, signals, zoneless, Angular Material, Jest). Served by `ng serve` locally (via Aspire) and as static files on S3 + CloudFront in production. Mirrors `BluefinWiki/frontend` conventions.

## Where things are

- `src/app/core/auth/` — Cognito Hosted UI sign-in (auth code + PKCE S256, no client secret): `cognito-oauth.ts` (authorize URL, token exchange), `auth.ts` (session/user signals, token storage, refresh, `signOut()` = local clear only; `logout()` = the explicit user sign-out: clears local state, sets sessionStorage `nabbit.signedOut`, then redirects to `https://{cognito.domain}/logout?client_id={clientId}&logout_uri={origin}/` (`{origin}/` is the only CDK-allowed LogoutUrl); with disableAuth it does not redirect. On landing at `/` -> `/recipes` -> guard -> `/signin`, the flag makes `/signin` show a "Sign in" button instead of auto-redirecting into the Hosted UI), `auth-guard.ts` (signed-out users go to `/signin`; the wanted URL is remembered so a share-target `/import?...` survives sign-in), `auth-interceptor.ts` (adds `Authorization: Bearer <id token>` to calls whose parsed origin (and path prefix) equals the API base only, not a string prefix so lookalike hosts are excluded, one refresh-and-retry on 401, else sign out).
- `src/app/app.html` / `core/shell/avatar-menu.ts` — app shell. A sticky top bar (app name left, avatar right) and the bottom nav (Recipes and Lists only; no Sign out) render under the same `showNav` condition: authenticated and not on `/signin` or `/callback`. The bar's height is the shared CSS variable `--top-bar-h` (56px + 1px border + safe-area top inset, defined in `styles.scss`), which also drives `scroll-padding-top` and the `/lists` sticky quick-add offset, so change it in one place. `AvatarMenu` (`app-avatar-menu`) is a round button showing the initial of the display name, else the email, else `?`, on a colour hashed from the user id (fixed saturation/lightness; a spec asserts white text has at least 4.5:1 contrast for all 360 hues). It opens a popover with name, email and Sign out; Sign out is an output and the shell's `signOut()` calls `Auth.logout()` (Cognito Hosted UI logout), or with auth disabled routes to `/signin` (the mock "Local Dev User"). The popover closes on outside click, Escape, Tab (focus returns to the button) and on every navigation: the shell binds `closeRequested` to a counter incremented on each `NavigationEnd`, and the input closes on any value change, so a constant binding would never close it. Opening moves focus to Sign out.
- `src/app/core/api/` — `ApiClient` (a typed method per backend route: recipes, images presign/upload, import, image import, lists, items, suggest) and `api.types.ts` (response shapes; domain types come from `@nabbit/recipe-core`). No API data is cached by the service worker.
- `src/app/features/` — lazy routes `/recipes`, `/recipes/:id`, `/lists`, `/import` (all behind the guard), plus `/signin` and `/callback`. `/recipes` is the recipe browser (debounced search, tag chips, skeleton/error/empty states, FAB to `/import`; a large/small/list view toggle remembered in `localStorage` `nabbit.recipeView`; every card/row has a delete button via `RecipeDeleter`); `/import` is the paste-or-share screen (https value sent as {url}, else {text}; share-target url, else first URL in text, auto-imports; preview with metric ingredients (the best photo candidate is flagged "Photo found, will be saved" but thumbnails load only after a "Show photo options" tap, to avoid hot-linking a third party; the user can pick another candidate, upload their own or remove it), heuristic banner, "AI-assisted - check the ingredients" banner for `confidence: 'ai'`, inline edit; an Instagram URL is auto-fetched by the server, but when any URL import answers 422 `needs_text` (Instagram: login wall, no caption, fetch error or auto-fetch off; other sites: a page with no readable text, e.g. JavaScript-built) the screen shows a paste prompt (generic wording for non-Instagram) and the box then sends the pasted caption as text (even if it starts with https://), remembering the URL as `sourceUrl`; for Instagram sources a "Recipe in a comment? Paste it here to add it" appender has two modes: when the caption is known (the user pasted it here) it re-imports caption + comment and REPLACES the draft with the result; when the caption is not known (the server auto-fetched it) it imports just the comment and MERGES it into the existing preview (`mergeDrafts`: new ingredients and steps appended at top level, duplicates by lower-cased text skipped, steps checked against every depth of the existing tree, extra groups kept intact minus duplicate leaves and groups left empty, photo choice kept). Instagram URLs are canonicalised (`canonicalInstagramUrl`: posts reduced to `https://www.instagram.com/{p|reel|reels|tv}/{id}/`, share params dropped) before they are sent and before they are saved as `sourceUrl`; Save -> `importImage` for the chosen candidate (on failure a "Saved without a photo" snackbar and the recipe saves anyway) -> POST /recipes -> /recipes/{id}); `/lists` (`features/lists/lists.ts`) is the shopping screen: list picker buttons + new/rename/delete (default list "Shopping" auto-created), items grouped by aisle in `CATEGORIES` order (checked struck through, last in group), tap toggles (optimistic PATCH, rollback on failure), double-tap (2 taps within 300 ms, no re-toggle) deletes with a 5 s "Deleted / Undo" snackbar (Undo re-POSTs name+category), sticky quick-add with debounced `suggest` autocomplete (keeps focus), long-press (500 ms) opens an aisle picker (PATCH category), one retry on 409.
- `features/recipes/recipe-editor.ts` — shared `app-recipe-editor` form (title, servings, tag chips, photo pick -> presign -> direct S3 POST -> `imageKey`, ingredients as qty/unit/name/note (a "Default scale-by" radio group on anchor rows plus a "No default" option edits `scaleBy`; cleared when its row is removed or stops being an anchor; `originalSize` passes through untouched) with `toMetric` re-run and `original` dropped on edit, CDK drag-reorder for ingredients, a tree of steps and groups (`step-rows.ts` holds the pure rows-to-StepNode conversion and indent/outdent/move/depth-guard logic; Add step/Add group per level, Indent/Outdent buttons, drag-reorder within a level, confirm before deleting a non-empty group; flat recipes stay flat), 409 conflict banner with Reload). Used by `recipe-edit.ts` (`/recipes/:id/edit`: save with `version`, delete with confirm + Undo snackbar -> restore, dirty guard `core/guards/unsaved-changes-guard.ts`) and by the import preview. `recipes/recipe-deleter.ts` (`RecipeDeleter`) is the shared confirm -> soft delete -> Undo (restore) flow used by the list, detail and edit screens. `lists/list-target.ts` (`ListTarget`) resolves which list new items go to (last used via `nabbit.lastListId`, else "Shopping", else the first) and is shared by the lists screen, the add-to-list dialog and the detail page's per-ingredient add button (one tap adds that single scaled ingredient, snackbar with Undo). `recipe-detail.ts` renders `steps` recursively (nested `<ol>`, `<h3>` for a group heading, metric temperature conversion via `mapSteps`) and has a "Scale by" selector (Servings stepper, or one entry per scalable ingredient with a quantity: an amount box + same-family unit select; one `factor` signal feeds the scaled ingredients, servings are derived and rounded to 0.5, "Save as new size" is allowed only when the derived servings are within the stepper's range, Reset shows while factor !== 1, opens on `recipe.scaleBy` when it is an anchor; pure helpers in `recipes/scale-state.ts`) and also offers "Save as new size (N servings)" (confirm dialog `shared/confirm-dialog.ts` listing before -> after, then PUT the scaled ingredients; the first save also writes `originalSize` = the pre-save servings + ingredients; once present it is sent unchanged and never overwritten) and, when `recipe.originalSize` exists, "Restore original size" (`recipes/restore-size-dialog.ts`: current -> original per ingredient by id, changed lines marked with text, added/removed since, lost-changes warning; confirm PUTs the original servings/ingredients with `originalSize` omitted and `scaleBy` cleared when its ingredient is not in the original; 409 reuses the reload offer). "Add to list" opens `recipes/add-to-list-dialog.ts` with the scaled ingredients and unit mode: list picker (last used list in `localStorage` `nabbit.lastListId`), one checkbox row per ingredient (to-taste unticked), one `POST /lists/{id}/items` batch. The list item is the ingredient name with the scaled quantity as a suffix, e.g. `flour (480 ml)` (no suffix when there is no quantity); category is left unset for server item memory. `core/api/image-url.ts` turns an `imageKey` into a URL via `environment.imageBaseUrl`.
- `public/manifest.webmanifest` — name, `start_url: /recipes`, standalone, 192/512/maskable icons, `share_target` (GET `/import` with `title`, `text`, `url`).
- `ngsw-config.json` — app-shell and asset caching only (production builds).
- `scripts/build-env.mjs` — writes `src/environments/environment.production.ts` from env vars; runs as the `prebuild` hook.
- `scripts/generate-icons.mjs` — regenerates the placeholder PNG icons (`npm run icons -w frontend`).

## Build-time configuration

`npm run build -w frontend` reads `NG_APP_API_BASE_URL`, `NG_APP_COGNITO_REGION`, `NG_APP_COGNITO_USER_POOL_ID`, `NG_APP_COGNITO_CLIENT_ID`, `NG_APP_COGNITO_DOMAIN` (host only, no scheme) and `NG_APP_COGNITO_REDIRECT_URI`. All six set: validated (https, non-local API) and baked in. None set: a placeholder environment is written so CI compiles (not deployable). Some set: the build fails. Optional `NG_APP_IMAGE_BASE_URL` (default `/img`, the same-origin CloudFront image path; set only if images are served from another origin) is outside that set. `environment.production.ts` is committed as the placeholder; the build rewrites it.

Output is `dist/browser/` (`index.html`, `ngsw.json`, hashed chunks), which is what Home's Deploy Nabbit workflow locates and syncs.

Local dev (`ng serve`, `environment.ts`; the Angular dev server excludes `@nabbit/recipe-core` from prebundling in `angular.json` because Vite cannot resolve its extensionless TS imports): API `http://localhost:3000`, auth disabled with a JWT-shaped mock token (`mockDevToken` in `auth.ts`, `sub` = the dev user, which the local backend decodes). The `e2e` build configuration swaps in a generated `environment.e2e.ts` (same, other API port); see `../e2e/SYSDOC.md`.
